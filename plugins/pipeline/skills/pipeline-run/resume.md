# Resume

1. `{ "action": "begin", "item": "p12" }` for the active item `get` named (or the `blocked` one the user named): it reuses the worktree and branch, recreating the worktree from the pushed branch when the folder is gone, and answers where the item stands. Enter the worktree it names (`EnterWorktree` with `path`; not in a child session, which is already there).
2. **An item with no tasks** (direct mode): look at what is there, `git status --porcelain` and `git log --oneline <base>..HEAD`, read the spec, and go on building from that. A `gate red` state → fix and `gate`. A `gate run` state with no pull request → open the PR (step 4). An item with a `pr` → `merge`, or `close` when it is already on `mainBranch`.
3. **An item whose ledger has tasks** (the full loop): read `full.md`. A commit after the verified one is an implementer's claim, not verification: run the task's check yourself. Continue from the state: `planning` with no tasks → its Plan step; `planned` or `task N accepted` → its Dispatch step; `implementer dispatched`, `fix round R dispatched` or `review dispatched` → the Agent call again with the brief already on disk (the open dispatch's `brief` in `status p12`), or the `brief` call again when the file is gone; `final review dispatched`, `gate red` or `gate run` → its final review and gate step.
4. Say so in one line: `p12 · resumed · gate red` or `p12 · resumed at task 3/6 · fix round 2`.
