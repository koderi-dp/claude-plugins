# pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `pipeline` plugin: a structured backlog, four skills that take a request to a merged PR with no approval gates, a watchdog over subagents that escalates once and then blocks, a migration skill for projects that run their own process today, and a status block as text and as a panel.

**Architecture:** One mod (`hooks/register.tsx`) wires engine hooks to pure modules: `hooks/files.ts` (paths, safe JSON read and write), `hooks/config.ts` (defaults, validation, the config drafted from a project), `hooks/backlog.ts` (items, order, readiness, BACKLOG.md), `hooks/ledger.ts` (ledger merge, text), `hooks/watch.ts` (agent table, activity line, the four signals), `hooks/status.ts` (the status block), `hooks/pane.tsx` (the panel). Four skills and four brief templates tell Claude what to do; the mod records, enforces protected paths and watches. Nothing from `board` or `superpowers-flow` is imported.

**Tech Stack:** Claude Code function hooks (`claude-code`, `claude-code/testing`), TSX panes, JSON files through `$.fs`. Tests run with `claude plugin test plugins/pipeline`.

**Spec:** `docs/superpowers/specs/2026-11-05-pipeline-design.md`

## Global Constraints

- Plugin folder `plugins/pipeline/`, plugin name `pipeline`, version `0.1.0`, MIT, author Danijel Peric. Tool name as the model sees it: `mcp__pipeline__pipeline`. Pane id `pipeline`. One command, `pipeline`, with the subcommand as its argument.
- Needs Claude Code v2.1.287 or later (mods); the README says so, with the version it was tested on.
- Project files under `<root>/docs/pipeline/`: `config.json`, `rules.md`, `backlog.json`, `BACKLOG.md`, `specs/`, `plans/`, `ledgers/<id>.json`, `ledgers/<id>/`. `root` is `(await $.session.repo())?.root ?? await $.session.root()`: the main checkout even from a worktree. Live file `<root>/.git/pipeline-live.json`, or `~/.claude/pipeline/<sha1 of root, 12 hex>.json` without a repository.
- JSON files are written as `JSON.stringify(x, null, 2) + '\n'`; every write re-reads the file first and merges; a file that fails to parse is never overwritten and the error names the line. Unknown fields survive a read and a write.
- Item statuses: `inbox`, `ready`, `planning`, `building`, `review`, `merged`, `blocked`, `parked`. Array order is priority.
- A tool call with `agentId` set answers `{ result: 'ignored: subagents do not write the pipeline' }` and changes nothing.
- Every hook handler catches its own errors and leaves state unchanged; the engine never sees a throw from this plugin.
- Pure modules never import from `claude-code`; they take and return plain data so tests need no engine.
- English only, sentence case. Palette: running `#8f8cf4`, done `#5fbf8f`, blocked `#e8a33c`, muted through `dimColor`.
- No model identifier in commits, PR text or comments; brief templates end with the attribution lines the session was given.

## Review Focus

1. A `backlog.json` edited by hand into invalid JSON: `add` refuses, answers the parse error with its line, the status block shows that line, nothing is overwritten. (Task 3)
2. An item whose `needs` lists an id that is `parked` or does not exist: it is never `ready`; the status block names why. (Task 2)
3. A subagent with no `turn.step` for `silentMinutes`, then the session restarts: the live file still lists it, the next `get` carries both a silent and a dead signal, and each signal is delivered once. (Task 5)
4. A subagent calls `Edit` on `.github/workflows/ci.yml` with `protectedPaths: [".github/workflows/**"]`: the call is denied with a message naming the rule; the main session's same call is allowed. (Task 5)
5. `migrate` on a copy of catalo's `docs/backlog.md`: every unchecked top-level item and every "Named follow-ups" bullet becomes an `inbox` item with the file in its note; checked items with a PR link become `merged` with the PR; no item is invented. (Task 9)

### Task 5: Watchdog: agents, signals, protected paths, live file

**Files:**
- Create: `plugins/pipeline/hooks/watch.ts`, `watch.test.ts`, `hooks/live.ts`, `live.test.ts`, `hooks/watch.hooks.test.ts`
- Modify: `hooks/register.tsx`

**Interfaces:**
- `watch.ts` (pure): `activityOf(call)` → one short phrase from a tool call (`editing <basename>`, `running <first word or two of the command>`, `reading <basename>`, `searching "<pattern>"`, `waiting on a browser page`; never the raw command); `normalizeCommand(cmd)` for loop detection (trim, collapse spaces, drop env assignments); `onSpawn`, `onStep(usage)`, `onCall`, `onComplete` returning the next agent list; `signals(agents, config.limits, now, previous)` → the four kinds of spec §8: `silent` (no step for `silentMinutes`), `looping` (the last three normalised commands equal and each failed, or `failures > fixRounds`), `budget` (`taskMinutes` passed), each raised once per agent per kind; `deadAgents(liveFromDisk, thisSessionId)` → agents listed running by a previous session instance.
- `live.ts`: `withEntry`, `parseLive`, paths from `files.ts`; one entry per session, heartbeat on every change throttled to 2 s and on `turn.complete`.
- Hooks in `register.tsx`: `agent.spawn`, `turn.step` (records `lastStepAt` and token usage per agent), `tool.call` (activity, command and failure tracking from the result's `isError`; and the protected-path deny: a subagent's `Edit`, `Write`, `MultiEdit` or `NotebookEdit` whose path matches `config.protectedPaths` answers `{ deny: 'pipeline: <path> is protected by docs/pipeline/config.json protectedPaths' }`), `turn.complete`, `session.start` (dead-agent detection from the live file, then this session's fresh entry), `session.end`. Signals go to the `signals` atom and, when `config.notify` is not `off`, to `PushNotification` through `$.tool.call`, falling back to `$.ui.toast`.
- Wake-up between items: on `turn.complete` of the main session while any agent runs, call the host's `ScheduleWakeup` if the tool exists (`$.tool.call`, ignore failure) with `delaySeconds = silentMinutes * 60` and a prompt "pipeline: check the watchdog signals with the pipeline tool"; never more than one pending.

**Steps:**
- [ ] Pure tests: activity phrases for a 600-character Bash one-liner; loop detection on three equal failing commands; silent after the limit, raised once; budget after `taskMinutes`.
- [ ] Hook tests with a mock clock: Review Focus 3 (silent then restart → silent and dead, each once); Review Focus 4 (deny for the subagent, allow for the main session); glob matching with `**`.
- [ ] Implement. Commit: `pipeline: watchdog, protected paths and the live file`.
