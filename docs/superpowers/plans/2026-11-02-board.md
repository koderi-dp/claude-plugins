# board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `board` plugin: a panel with this session's tasks, subagents (one activity line each) and sibling sessions, plus a project board of milestones and items kept in `docs/superpowers/board.json` by Claude through one tool and a skill.

**Architecture:** One mod (`hooks/register.tsx`) wires engine hooks to two pure modules: `hooks/board.ts` (board file shape, merge, plan import, text rendering, activity line) and `hooks/live.ts` (the per-session live file and staleness). A skill tells Claude when to write the board. No agents, no settings beyond `autoOpen`.

**Tech Stack:** Claude Code function hooks (`claude-code` module, `claude-code/testing`), TSX panes with `Box`/`Text`/`Button`, JSON files through `$.fs`. Tests run with `claude plugin test plugins/board`.

**Spec:** `docs/superpowers/specs/2026-11-01-board-design.md`

## Global Constraints

- Plugin folder `plugins/board/`, plugin name `board`, version `0.1.0`, license MIT, author Danijel Peric. Tool name as the model sees it: `mcp__board__board`. Pane id `board`. Commands: `board` only, with subcommands as its argument.
- Needs Claude Code v2.1.287 or later (mods); the README says so, as superpowers-flow's does.
- Board file: `<root>/docs/superpowers/board.json`, `JSON.stringify(board, null, 2) + '\n'`. Live file: `<root>/.git/board-live.json`, or `~/.claude/board/<sha1 of root, 12 hex>.json` without a repository. `root` is `(await $.session.repo())?.root ?? await $.session.root()`.
- Item statuses: `backlog`, `next`, `in_progress`, `blocked`, `done`. Milestone statuses: `planned`, `active`, `done`. Unknown fields on any object survive a read and a write.
- Every hook handler catches its own errors and leaves state unchanged; the engine never sees a throw from this plugin.
- A `board` tool call with `agentId` set answers `{ result: 'ignored: subagents do not write the board' }` and changes nothing.
- Palette: running `#8f8cf4`, done `#5fbf8f`, blocked `#e8a33c`, muted text through `dimColor`. English only. Sentence case.
- Pure modules never import from `claude-code`; they take and return plain data so tests need no engine.

## Review Focus

1. A `board.json` edited by hand into invalid JSON: the tool refuses to write, answers the parse error with a line number, and the panel shows that line instead of an empty board. (Task 4)
2. A plan whose task headings carry trailing text or Windows line endings (`### Task 3: Croatian and English UI with Paraglide\r`): import still yields 9 items with clean titles. (Task 2)
3. A subagent's last tool call is a 600-character Bash one-liner with `&&` and env assignments: the activity line is one short phrase, never the raw command. (Task 5)
4. Two sessions heartbeat into the live file in the same second: neither entry is lost after both writes, since each write re-reads first. (Task 3 and Task 6)
5. A session in a worktree with the main checkout's board present: it reads and writes the main checkout's file and never creates `docs/superpowers/board.json` in the worktree. (Task 4)

### Task 2: Board module: parse, merge, import, text

**Files:**
- Create: `plugins/board/hooks/board.ts`, `plugins/board/hooks/board.test.ts`, `plugins/board/hooks/fixtures/catalo-plan.md` (the heading lines of catalo's plan: a `# Phase 1, Plan 1: Foundation Implementation Plan` line, nine `### Task N: <title>` lines with the titles from the spec's catalo example, each followed by two `- [ ] **Step` lines, CRLF line endings)

**Interfaces:**
- Produces, all exported from `board.ts`, pure:

```ts
export type Parsed = { ok: true; board: Board } | { ok: false; error: string }
export function parseBoard(text: string): Parsed            // error names the JSON position as "line N: <message>"
export function emptyBoard(): Board                            // { version: 1, milestones: [] }
export type Update = { goal?: Goal; milestones?: Array<Partial<Milestone> & { id: string; after?: string; items?: Array<Partial<Item> & { id: string; after?: string }> }>; remove?: string[] }
export function applyUpdate(board: Board, u: Update, nowIso: string): Board
export type ImportInput = { plan: string; text: string; milestone?: Partial<Milestone> & { id?: string } }
export type Imported = { ok: true; board: Board; milestoneId: string; count: number } | { ok: false; error: string }
export function importPlan(board: Board, input: ImportInput): Imported
export function serialize(board: Board): string               // JSON.stringify(board, null, 2) + '\n'
export function anchorOf(heading: string): string             // GitHub-style: lowercase, spaces to '-', drop chars outside [a-z0-9-]
export function statusText(board: Board | null, error: string | null, live: Live, agents: AgentRun[], tasks: NativeTask[], at: number, scope?: 'all' | string): string
export function findText(board: Board, query: string): string
export function attention(m: Milestone, live: Live): { kind: 'blocked' | 'in_progress' | 'next' | 'none'; count: number; text: string }
```

- Merge rules (`applyUpdate`): match milestones and items by `id`; fields given replace, fields left out stay; a new id appends, or goes right after `after`; a status that changes sets `updatedAt` to `nowIso` on items; `remove` drops milestone or item ids anywhere; `goal` replaces whole. Unknown fields survive.
- Import rules (`importPlan`): items from `/^### Task (\d+):\s*(.+?)\s*$/m` on text with `\r` stripped, id `t<N>`, `ref` = `<plan>#<anchorOf(full heading without '### ')>`, status `backlog`; milestone id = `input.milestone.id` or the plan file's base name without date prefix and extension (`2026-10-29-phase1-foundation.md` gives `phase1-foundation`), title = `input.milestone.title` or the first `# ` line, `ref` = plan path, status `planned`, or `active` when the board has no other milestone; existing items keep `status`, `note`, `updatedAt`; no headings gives `{ ok: false, error: 'no "### Task N:" headings in <plan>' }`.
- `statusText` layout (used by the tool's answers, `/board status`, and tests), one line per row, two-space indent for sublines:

```
Board · 5/9 done                       (or "Board · <goal.title> 21/36" with a goal; "No board. /board init reads the plans and the ledger." with none; "Board: <error>" on a parse error)
Active
  ● phase1 · Phase 1 Foundation · 5/9 · 2 blocked: WIP commit on task-7, checks not run
Planned
  ○ q8 · Thread following and threads view · 0/3 · needs q7 · M
  … and 18 more planned
Done
  ✓ 35 milestones, latest: Webhook corpus
Now
  tasks: 1 in progress, 1 pending
  ● Review Task 6 (spec + quality + visual) · opus · 5m 47s · running npm run dev
  ✓ Implement Task 6: gallery UI · 23m · 43 calls
  sessions: Implement Q8 threads · feat/q8-threads · q8/t2 · 1 agent · editing web/src/threads/following.tsx
```

With `scope: 'all'` every milestone lists every item under it (`  ● t2 · Threads I follow view · in_progress · 12m · <note>`); with `scope: '<id>'` that milestone alone, in full, plus its `closes` lines. `attention` picks, in order: blocked (count and first note), in_progress (count, item title, and the live agent's model and elapsed when a live session holds it), next (`next: <title>`), none.

### Task 5: Agents and native tasks with an activity line

**Files:**
- Modify: `plugins/board/hooks/board.ts` (add `activityOf`), `plugins/board/hooks/board.test.ts`, `plugins/board/hooks/register.tsx`
- Create: `plugins/board/hooks/agents.test.ts`

**Interfaces:**
- Produces in `board.ts`:

```ts
export function activityOf(call: { tool: string; [k: string]: unknown }): string
```

Rules: `Edit`/`Write`/`NotebookEdit` give `editing <basename of file_path>`; `Read` gives `reading <basename>`; `Grep`/`Glob` give `searching "<pattern>"` cut to 40 chars; `Bash`/`PowerShell` give `running <first 3 words of the last command segment>`, where the segment is the last `&&`-separated part after stripping leading `VAR=value` assignments and `export VAR=…;` pieces, the whole cut to 48 chars with `…`; `Agent` gives `delegating <description>`; `WebFetch`/`WebSearch` give `fetching <host or query>`; any `mcp__…browser…` or `mcp__playwright…` tool gives `waiting on a browser page`; a `TaskCreate`/`TaskUpdate` gives `updating tasks`; anything else gives `using <tool name without the mcp__ prefix>`.

- Produces in `register.tsx`: atoms `agents` (`AgentRun[]`, capped at 200), `tasks` (`NativeTask[]`), `now` (number); hooks:
  - `agent.spawn`: after `next`, push `{ id: started.agentId ?? e.tool_use_id, agentId: started.agentId, name: e.description, model: started.model, status: 'running', startedAt, calls: 0, activity: 'starting' }`; `autoOpen` when the setting is `always` (Task 7 supplies `openPane`; until then a no-op).
  - `tool.call` (unfiltered): when `e.agentId` matches a running agent, set its `activity = activityOf(e)` and `calls + 1`; when there is no `agentId` and `e.tool` is `TaskCreate`, append `{ id: <tool_use_id>, subject, status: 'pending' }` to `tasks`; `TaskUpdate` with `status` sets it (`deleted` removes; the engine's task ids are not known to the mod, so match by `taskId` against ids the mod assigned, and when none matches, by subject).
